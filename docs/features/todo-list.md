# 块编辑器 · 待办列表（todo list）—— 对齐 spec

> 建档 2026-07-23（随 todo-list UX sweep 修复 PR-A）。此前 `docs/features/` 无任何 spec 拥有 todo 行为——仓库铁律要求改 todo 交互的 PR 同 PR 更新本 spec。本份覆盖 `<ul class="ws-todo">` 待办列表的创建、勾选、键盘流、剪贴板、转换、视觉。行为契约以 todo-list 修复计划各单元的「期望行为」为准，随 PR-A→E 逐批补全（当前只落地了 PR-A 的三条，其余待各 PR 移入契约）。

## 行为契约

**是什么。** 待办列表 = `<ul class="ws-todo">`，每个 `<li>` 前有一个可点的勾选框；勾选态存在 `<li data-checked="true">`（未勾选**不写** `data-checked`）。勾选框、划线、蓝底✓的视觉由入盘语义 CSS（`data-ws-schema-css="todo"`）承载，随文件落盘，浏览器直开即真 checklist。

**创建。** 两条路：① 空正文块打 markdown 快捷 `[] `（或 `[ ] `）+ 空格 → 转成待办；② 斜杠菜单选「待办」。两条路产出的空项都必须**可继续打字**——空 `<li>` 必带占位内容（`<br>`），否则 `list-style:none` 让空 li 高度为 0、光标落不进、输入被吞（create-1，PR-A 已修）。行中间打 `[] ` 不转换（负例，保持）。

**勾选。** 点勾选框（gutter，条目内容左缘左侧）只切 `data-checked`、不进编辑态、不放光标、后续按键不改条目文字（check-1，PR-B 已修）。在编辑该项文字时点勾选框：勾选翻转、光标留原位、继续打字落原处。勾选视觉：文字变灰 + 划线、框变蓝底白✓；取消勾选完全还原。勾选态落盘、关开重开保留、不触发降级。

**键盘流。** 项内 Enter 分裂产出的新项永远未勾选、不复制源项 id（doc-linking 锚点不重复）——属性跟内容走（劈半时后段剥、行首回车时上方空项剥）（keys-2，PR-B 已修）。块末 Delete 与 Backspace 对称：末项尾 Delete 并入下一叶子块、段末 Delete 吞列表首项、空项 Delete 并入下一项，光标均落接合点；不可并块（图片等）安全无反应（select-3，PR-B 已修）。

**行首退格 = 逐层剥离（E1，2026-08-04 对拍定稿）。** Colin 拍板「Notion 怎么做我们怎么做」。Notion 实证（每条探针都用哨兵字符自证过光标落点，不是推断）：**顶层列表行**行首按退格，第一次**只剥掉列表格式**——该行原地变成文本块、列表在此处劈开、**不与上一块合并**；**第二次**才并入上一块。空行 / 唯一行 / 已勾选待办走同一条规则（勾选态随格式一并丢弃，Notion 同款）。**终态与旧的一次性合并完全一致，只是推后一次按键**——所以 `#319`（Wendi bug3「行首退格什么都不发生、不上移」）的诉求完整保留：第一次按键就有明确可见的反馈。实现直接复用行菜单「转为正文」的 `turnIntoLines`（顺带继承保 `start`、保子项两条加固）。

**嵌套行不走剥离（文法天花板）。** Notion 第①步是「嵌套的文本块」，我们的 `<li>` 只装行内内容或子列表，表达不了 → 压成 Notion 的第②步：有前兄弟→并入前兄弟；无前兄弟→并入宿主行文字，**后续兄弟仍留在父下**。实测这恰好就是原生行为，故嵌套行一行未改。**标题块不在此列**：实测 Notion 对标题是**直接合并、不剥格式**，与列表/toggle 分道，我们保持原样（别一起改）。

**「上一块是列表」的合并形态。** 段落行首退格并入上一个列表时，并进**「视觉上的上一行」的文字**拼成一项，**不是追加成新列表项**，也**不是**并进「最后一个直接子项」——末项带子项时它在屏幕上不是上一行，它下面还压着自己那堆子行。目标要沿末项的子列表**下钻到最深**（`lastVisibleLi`）。Notion 实测：`- A / 　- A1 / 　- A2 / 段落文字` → 段落并进 `A2`。并进父行 A 会让文字**跳到子项上方**，子项越多跳得越远（十个子项跳十行），用户读成「文字被搬走了」。删空块后的光标落点同理。⚠ 这条第一版实现成了「最后一个直接子项」，是对拍证据没覆盖嵌套情形所致（原对拍用例是平列表）——补量后才发现。原文如下（Notion 实测：`父后行` + `分隔二` → 一项 `父后行分隔二`）。这也是列表行剥离后再退一次的落点，两条路径必须同款。⚠ 断言这条时**只看块级 textContent 是哑门**——「一项『甲乙』」和「两项『甲』『乙』」的块文字长得一模一样（变异自检实测：改回追加成新项，只看块文字的断言照样全绿），必须逐项查 `li`。

**空块删除后光标必须落进列表末项【内】。** 删掉空块、光标回到上一块时，若上一块是列表，`enterEdit(mode:'end')` 会把光标停在 `<ul>` 层（末项之后）而非末项内 → `closest('li')` 取不到项，后续退格既进不了行级剥离也进不了原生合并 = **死键**（实测连按三次第三次起纹丝不动）。必须显式把光标放进末项，且**全空的 `<li>` 要先补 `<br>`**（否则 selection 变 null）。门：`e2e/list-backspace-peel.spec.js` E1-10。

**空壳宿主行必须占住自己那一行（Colin 2026-08-04 实机试玩抓到）。** 一个 `<li>` 自己没有任何内容、只裹着一个嵌套列表时（由 Tab 缩进到空行之上、或原生合并产生），它自己的勾选框/marker 会与嵌套首项的挤在**同一行**——空 `<li>` 高度几乎为 0，两个绝对定位的 `::before` 落到同一个 y。修：在 `markDirty` **和 attach 两个出口**归一，给这类宿主行补一个占位 `<br>`。⚠ **只挂 markDirty 不够**——已经被写坏的老文档要等用户敲一下才自愈，打开时照样是坏的。门用**几何断言**（宿主行与嵌套首项的纵坐标必须错开一个行高），结构断言咬不住这个纯视觉症状。

**嵌套行行首退格由我们自己接管，绝不交原生。** 语义仍是 Notion 的第②步（并入前兄弟；无前兄弟则并入宿主行文字），但**实现不能交给原生 contenteditable**：Chromium 合并时会把「打字样式」包成 `<span style="font-family: -apple-system, …">` 写进磁盘，且在「前兄弟是空行」时把结构搅成空壳宿主行。⚠ 断言这条时**前置结构必须是「前兄弟是空行」**——变异自检实测，前兄弟非空的用例上这条断言是哑的（把接管改回原生，它照绿）。合并机制统一走 `mergeLiInto()`（剥占位 `<br>` / 插在子列表前 两条加固此前散在三处，改一处漏两处）。门：`e2e/list-nested-merge.spec.js`（5 条）。

**gutter「+」点下去立刻弹块类型选择器（E5，2026-08-04 对拍定稿）。** Notion 实测：点「+」→ 插入一个空文本块**并同时弹出选择器**；该空块的占位在选择器开着时变成 “Type to filter…”；按 Escape **只关选择器、空块留下**（不回滚插入）；其 aria-label 写着 “Click to add below. Option-click to add a block above”，⌥ 插上方与我们既有一致。这是**全局 gutter 行为**（所有块类型旁边点都该弹），不是列表专属。嵌套行的「+」仍只插同层新行、不弹（产物是 `<li>` 不是块，同既有结构性分歧）。

**实现上的三条硬约束**：① 确认时往回删的字符数是 `query.length + (typed ? 1 : 0)`——从「+」进来块里没有字面 `/`，删它就是删自己没插入的东西；⚠ **这条当前没有门能咬住**（变异自检实测：去掉 `typed` 判断七条全绿，因为每个块是独立 contenteditable、`selection.modify` 跨不出块边界，多删那一下打在空气上），留着是为了块模型万一收敛成单一 contenteditable 时不变成丢数据 bug；反方向能咬住（不删 query → 筛选字残留成正文）。② 「正在选类型」的标记必须挂在**文档根**、不能挂到块上——挂块上等于在正文做一次 DOM 变更，undo 管理器会记成独立一步，「插入 + 弹选择器」要按两次撤销才回得去。③ 九处散落的「就地关菜单」统一走 `closeSlash()`，否则标记残留、占位永远卡在筛选提示。门：`e2e/plus-picker.spec.js`（7 条，含钉住「打 `/`」老路仍要删掉字面斜杠那条）。

**undo/redo 后可继续打字。** 撤销/重做后立刻打字必须落进文档（不被吞）——重写编辑区后按结构路径重进编辑，路径失效则落首个可编辑块；光标精确位置不还原（v1 取舍）（clip-3，不限 todo，PR-B 已修）。

**编辑流不得损坏文档。** 列表内选删后打字，绝不把空 `style=""` 残留写进磁盘——否则整篇判非合规、重开永久降级基础编辑（select-1，PR-A 已修，兜底在 `serialize.js` cleanRoot 通用剥空 style）。

**剪贴板。** 复制/剪切**部分**待办项（跨 li 但非整列表）→ 剪贴板打包成**块级 `ws-todo` 列表片段**（保留待办类型 + `data-checked`），绝不携带裸 `<li>`；粘进段落成合规待办块、绝不产生 `<p>…<li>` 非法嵌套（clip-1，PR-A 已修）。同一 `<li>` 内选一段字复制 → 仍走行内、并入目标段落纯文本。部分待办项粘进另一个同类列表 → 逐项并入当前项之后、保留勾选、**仍是单个 `<ul>`**（绝不劈成多个相邻 ul，对齐 bug2 纪律）。

**创建（斜杠/转换）产物不留占位。** 斜杠菜单在非空块插块产出**空产物**（补 `<br>` 保 caret），不种「列表项/引用内容/新标题/提示内容」等占位文本（否则前插入盘，create-2，PR-C 已修）。

**转换往返不塌缩。** 多项 todo「转为」文本再转回：按 `<br>` 拆行还原多项、不塌成单项（create-3，PR-C 已修）；勾选态经文本往返不保留（见有意分歧）。

**嵌套渲染两侧一致。** 裸嵌套非 todo 子列表（转换路径产物）编辑器内与浏览器直开都显圆点/编号、不可勾；Tab 缩进产生的 `ws-todo` 子列表保持无圆点 + 可勾（D3）（create-4，PR-C 已修，CSS class-scoped）。

**嵌套键盘。** 嵌套空项 Enter → outdent 成宿主下一兄弟（后继兄弟留在宿主嵌套里——空项当子列表父项时 Chromium 无法在块级 ul 前打字，故 Enter 空项不收编）、Backspace → 光标落宿主末尾，均不留幽灵空 ul（keys-3，PR-C 已修）；Shift-Tab 反缩进**非空**中间子项时收编后继兄弟为其子项、顺序不乱（keys-5，PR-C 已修）。

**勾选视觉不污染子项。** 勾选父项不划穿/不变灰未勾的嵌套子项——含子列表的勾选项只变灰不划线（避免 CSS 装饰传播），叶子勾选项照常灰+划线（check-2，PR-C 已修）。

**markdown 快捷覆盖扩展。** 空正文块（或块首前缀）打 marker+空格转换，覆盖：`[x] `/`[X] ` → 首项已勾待办；块首 marker+空格 + 后面已有文字 → 转换且保留后缀文字（前缀触发）；非 1 起始序号 `3. ` → `ol[start=3]`。转换**只在敲下补全 marker 的那个空格、且该空格紧邻块首文本节点里的 marker 末**这一击发生（绑 `insertText`+space + caret 恰停 `marker` 末的守卫）——① 删字到 caret 停 marker 末（如「- x」删 x 剩「- 」）走 `deleteContentBackward`，不误转；② 既有段落（磁盘/粘贴的「- 文本」）在任意位置敲空格，caret 不紧邻 marker，不误转、不吞 marker；③ 内容裹在行内元素里（`<b>…</b>`）时 marker 被打进行内元素、块首非文本节点，直接不转换（绝不清空整块丢内容）（create-7，PR-D 已修；②③ 由对抗审查补漏）。

**空项 Enter 脱离列表。** 顶层空项（不止末项，中间/首位同样）Enter → 脱离列表：删空项、按位置劈 `ul`（首位段落插列表前 / 中间后继项移到新同类列表、段落夹中间），光标落空段落。源空项的 `id`/`data-checked` 不迁移到脱列段落（段落带 `data-checked` 即非合规）（keys-7，PR-D 已修）。

**Tab 缩进保光标。** Tab 缩进列表项后光标保留在项内原位、不甩到项末（缩进重挂 DOM 后按记录的 anchorNode/offset 还原，失效才回退项末）（keys-8，PR-D 已修）。

**勾选与打字各自成步。** 打字后立刻点勾选框：`data-checked` 翻转前先 `checkpoint` 把 pending 打字冲成独立快照，一次 undo 只回退勾选、打字仍在（check-3，PR-D 已修）。

**转换保锚点 / 不塌缩。** todo「转为」文本：产物剥掉遗留的 `ws-todo`/`ws-callout` 语义 class，用户自定义 class 保留（create-5，PR-D 已修）；todo「转为」toggle：保留源块 `id`（doc-linking 锚点不断）、首项行内进 `<summary>`、其余项各成一个正文 `<p>`（create-6，PR-D 已修）；首项行内为空（仅嵌套子列表 / 空 li）时 `<summary>` 补 `<br>`、不留不可见空标题（对抗审查补漏）。

**「转为」只作用于选中的行（方案 B 第 2 步，Colin 2026-07-23）。** 选中**单个/部分** `<li>`（格式条「转为」）→ 只把那几行从列表**抽出去**转成目标块，前后剩余项仍是原列表；选中**整列表**（⌘A 两次）→ 维持整块转换（既有）。实现:把 `<ul>/<ol>` 在选中 li 跨度处劈成 `[前列表][选中行]([后列表])`、让选中 li 独占原 ul，再复用整块 `turnInto`（产物 / class 迁移 / `data-checked` 清理 / conform 全走既有逻辑）。选中的行由「与选区**内容非零交集**」判定（排除三击/`Home+Shift+↓` 把末端停在下一行最前沿这种零宽边界项，否则误多抽一行）。选中行「转为」它已是的列表类型 = 空操作（不裂成三张列表）。⋮⋮ 块菜单的「转为」仍整块。与 ⌘A 分级（`editor-select-all.md`）配套:⌘A 一次选当前行 → 「转为」抽这一行。**by-design**:从 `<ol>` 中间抽一行后，后段 `<ol>` 编号从 1 重启（不带 `start`）——对齐 Notion（编号列表被非编号块打断即重启），conform 不破。

**剪贴板 id 去重。** 块级复制粘贴到**同文档**：粘贴份剥掉与文档已存在块重复的 `id`（含后代、同批次内也去重），锚点/互链不被重复 id 破坏；跨文档粘贴不撞 id 则保留 id（护住互链锚点价值）（clip-4，PR-E 已修）。

**外部「- [ ] 」纯文本转 todo。** 外部纯文本多行粘贴，**全部非空行**都匹配 `- [ ] ` / `- [x] ` → 识别成待办：目标非列表则构造 `ul.ws-todo` 插块，目标是 todo 列表则逐行追加 li（仍单个 ul）；`[x]`/`[X]` 置勾选，marker 剥除。任一行不匹配 → 整段回落既有纯文本粘贴（不做混合解析）；目标是普通 bullet/numbered 列表维持字面（不扩）。只认纯文本模式、不引入外部富 HTML（不违反 ED-A4）（clip-5，PR-E 已修）。

**勾选热区几何。** X 命中带贴合勾选框体 ±4px 缓冲（右缘距文字左缘留 ≥4px 非勾选区，消「文字左缘零缓冲误触」）；Y 吸附最近直接子 li（±6px 容差，消项间 margin 死区、缝隙等距吸附上方项）；勾选框 `cursor:pointer`（check-4，PR-E 已修）。

**取消勾选删属性。** 取消勾选 `removeAttribute('data-checked')`、不写 `data-checked="false"` 脏字节；CSS/判定只认 `"true"`、`"false"` 与无属性等价，存量老文档下次翻转自然清洗（visual-5，PR-E 已修）。

**勾选框对比度（浅色）。** 未勾选边框对纸底 ≥ WCAG 3:1（`#cfccc6` 1.60:1 → `#8a857c` ~3.66:1）；已勾蓝底/✓ 字形本已 ≥3:1（visual-3，PR-E 浅色已修；深色见欠账）。

**跨 toggle 边界删除**见 `editor-cross-block-selection.md`（U23/select-4：部分跨界一致化为空操作 + 反馈动画）。

**行级手柄悬停跟随（粒度对齐 U1=A，分支 feat/ux-granularity，2026-08-03）。** 悬停列表块（todo / 普通 `ul`/`ol`，含 toggle 体内列表）内任一行，⋮⋮ 手柄跟随锚到**该行**左缘：嵌套行取最深 `li`、锚随缩进右移（对齐 Notion 逐行手柄）；悬停落在行间隙 / ul padding 按 Y 就近吸附到最近行，无手柄真空区。非列表块仍锚整块，跨块跟随不变。悬停本身零 DOM 变更（不脏档）。门：`e2e/list-row-grip.spec.js`（plan `docs/plans/2026-08-03-002-feat-todo-row-granularity-plan.md`，Colin 2026-08-03 拍板；A+B+C 整体完成才进 main）。

**Esc 在列表里分三档（Wendi 2026-08-05 反馈，与 ⌘A 已有的三档对称）。** ① 当前行 ② 整张列表 ③ 取消。

唯独 Esc 把底层容器暴露出来 —— 存储单元与交互单元解耦（方案 B）在这一处漏了。
⚠ **行灰选后按 Delete 必须走 `removeRow`、不能走 `removeBlock`**：后者只认顶层块，文档只剩这一个列表时它会把 `<li>` 原地
retag 成 `<p>`，产出 `<ul><p></p></ul>` —— 非合规、重开整篇降级。变异自检逼出来的：第一版门用了「周边还有别的块」的
fixture，那种形态下两条路径产出恰好一样，把行删除改回 `removeBlock` 照样全绿（哑门）。危险只在「文档只剩这一个列表」
与「删的是最后一行」两种形态暴露，门必须各覆盖一条。
门：`e2e/grip-scope-consistency.spec.js` E-1（几何断言：框高必须等于单行高）/ E-2（三档阶梯，且第二档的框必须真的更高）
/ E-3、E-3a、E-3b（行删除三形态）/ E-4（负向：非列表块仍是两档）。

**编辑态底色也是行级（2026-08-06，Wendi 同一条反馈的后半）。** 上面那档只修了 `Esc` 之后的**灰选**框；
**按 Esc 之前**、正在打字时的那层浅灰底（`data-ws2-editing`）仍画在整个 `<ul>` 上，于是编辑任何一行都把
兄弟行一起罩进去——Wendi 复测「这个 bug 还在」指的就是这半。实测：三行列表编辑第 2 行，承载底色的元素是
UL、高 93.6px（罩 3.3 行）；同文档段落对照恰好 28px = 自身。**列表是唯一「高亮范围 ≠ 正在编辑的东西」的
块类型。** 修法：底色改由 `<li>` 上的 `data-ws2-editrow` 承载（`enterEdit` / `onSelectionChange` / `exitEdit`
三处维护，取**最深** li，与 `rowOf` 同规则），CSS 把 `[data-ws2-editing]` 的底色排除 `ul`/`ol`。
⚠ **只下沉列表，不动多段容器**（callout / quote）：容器有可见边框，编辑框内某段时整框着色读作「你在这个
框里」是合理的；列表没有边框，整表着色读作「这些行是一个东西」，正是本 bug。语义不同，别一并改。
⚠ 清理必须**按属性扫 DOM**、不靠引用（`retagElement` 原样复制属性，只清引用必漏掉被换过标签的那个——
2026-08-05「清不掉的蓝底」同款病，team-memory 已立规）。
**漏网原因值得记一笔**：`grip-scope-consistency` E-1 的操作序列与用户复现**逐字相同**（点行→End→回车→
打字→Esc），但它直到按完 Esc 才开始量框高，而 bug 出现在按 Esc 的**前一个键**；全仓 e2e 对
`data-ws2-editing` 此前只有「在不在 / 是什么标签」的存在性断言、**从无几何断言**。
门：`e2e/todo-row-editing-highlight.spec.js` 7 条（断言读**真实 computed background** 找出谁被染色再量它的
盒子，不查属性）。两个实测坑写进注释：Chrome 把 `.015` 舍成 `.016`；alpha 窗口要上封顶到 `.025` 才能与
灰选态的 `.03` 分开（第一版写 `<0.05`，Esc 后灰选被当成编辑底色收进来，「退出清零」假红）。

**带子项的父行只染自己那一行（2026-08-06，对抗审查 ADV-2）。** 上面那档在**扁平**列表上对了，但
`<li>` 的边框盒天然包含它的嵌套子列表 → 编辑父行仍把整棵子树罩住（实测 93.6px，正是最初那个数字）。
用户路径只有五步：打一行 → 回车 → Tab → 打子项 → 点回第一行。修法：`li[data-ws2-editrow]:has(ul,ol)`
把底色换成 `1lh` 高的渐变（`background-origin:border-box`，正好覆盖该行自己那一行）。
⚠ **只钳带子项的行**：叶子行维持整盒着色，否则自己换行的长条目只剩第一行有底色（净退步）。
⚠ **不对 `[data-ws2-rangesel]` 做同款处理**：那边父行拿到标记的前提是 `covered()` 成立 = 整棵子树都在
选区里，连体着色恰恰是对的。这是有原则的区分，不是漏做。
门：`e2e/todo-parent-row-tint.spec.js` 2 条，**差分像素**——同一条竖带在未聚焦/聚焦两态各截一次，比
同一批像素的前后差（不依赖「取样带必须空白」这种脆前提，文字在两态里一模一样）。双向变异：摘掉钳制
→ 只 PT-1 红；把钳制误用到所有行 → 只 PT-2 红。
⚠⚠ **这段 CSS 有两个会让整条规则静默消失、而 `matches()` 照样 true 的坑，都实际踩过**：
① 它活在 **JS 模板字符串**里，注释里出现反引号会当场闭合模板串、整个编辑器样式连同其后代码一起废掉；
② 注释里出现**注释结束符的字面量**会当场闭合注释、吞掉紧随其后的规则（本条注释第一版为了引用
CLAUDE.md 那条同名教训而写了它的字面量，正好把自己下面那条规则吃了）。
⚠ 像素门必须**钉浅色外观**：默认 `system` 在深色开发机上给文档上暗色滤镜，取样整片发暗、断言全无意义。

**勾选框收在行选中框内（2026-08-06）。** 此前勾选框画在 `li` 盒**外**（`::before` 的 `left:-22px`，落在 ul 的
padding 里），于是行选中框（li 盒）把它漏在框外、整表选中框（ul 盒）又把它包进去——同一个勾选框两档选中
一会儿在框内一会儿在框外（实测行选框左缘 306.2、整表框左缘 279，差 27.2）。修法：负 `margin` 把 `li` 的
**边框盒**拉到与 ul 齐平，再用等宽**透明左边框**（`border-left:1.7em solid transparent`）把 padding 盒顶回原位。
关键是 padding 盒纹丝不动——`::before` 的包含块就是 padding 盒，所以勾选框的 `left:-22px` 保持常数、
绝对位置一字不动，文字也不动；变的只有边框盒（背景与 `box-shadow` 都按边框盒画，于是选中框把勾选框收了进来）。
嵌套缩进由每层 ul 自己的 `padding-left` 给、逐层对冲后一层都不塌。
⚠⚠ **绝不能写成 `padding-left:calc(1.7em + 4px)` + `::before{left:calc(1.7em - 22px)}`**（第一版就是这么写的，
对抗审查 ADV-1 实抓）：伪元素里的 `em` 按**伪元素自己的** font-size 解析，而既有的
`[data-checked="true"]::before{font-size:11px}` 改的正是它 → **一勾选，勾选框从 5.2px 跳到 −3.3px**（横移 8.5px），
`todoGutterHit` 又从渲染的 `::before` 反推命中带、带子跟着跳，结果是**同一个点第一下勾得上、第二下取消不掉**
（实测 `x = li.left+17.2` 两次都 `true`），且已勾的框重新掉出行选中框——正是本条要修的那个毛病。
⚠ `todoGutterHit` 与各 spec 的坐标换算都要补 `borderLeftWidth`：`::before` 相对 padding 盒、鼠标坐标相对边框盒，
加了透明边框后两者不再重合。
**漏网原因（与上一条同源、换了个维度）**：CB-1..CB-5 的 fixture 全是**未勾态**，几何断言到位了但
**状态维度（checked）没进 fixture 矩阵**。补 CB-6（勾选前后几何不变）+ CB-7（**鼠标不动**、点同一个绝对坐标
两次必须勾上再取消——此前的 helper 每次都重新从活的 `::before` 推坐标，等于跟着框一起移动鼠标，
把「手不动」这个前提偷换掉了）。变异验证：退回第一版几何，**只有 CB-6/CB-7 翻红**，其余五条仍绿。⚠ 连带拔掉一个脆弱契约：`todoGutterHit` 的 X 命中带原写死成 `[li.left-26, li.left-2]`
（「勾选框在盒外」时代的产物、与 CSS 隐式耦合），改几何当场失配、勾选整个失灵 → 已改为**从真实渲染的
`::before` 反推**（框体 ±4px 缓冲）。**用户实际点的区域一个像素没变**：新旧命中带的绝对位置都是
`[ul.left+1.2, ul.left+25.2]`。⚠ 五个 spec 里写死的「li 相对坐标」同步改为从渲染推导——`li` 盒左扩后
「相对 li 左缘 12px」从文字上挪进了勾选带，写死那版会点成勾选、不放光标。
门：`e2e/todo-row-selbox-checkbox.spec.js` 5 条（CB-3「文字与勾选框绝对位置不位移」是本单元的安全带，
新旧几何下都必须绿）。

**跨块选区罩到部分行时，那些行有块级蓝底（2026-08-06）。** 此前 `refreshRangeSel` 的 walk 只遍历
`blocksInScope`（= `root.children`），`<li>` 永远进不了集合——「从段落拖到列表第二行」这种**部分覆盖**一个
块级标记都不打，列表是唯一拿不到跨块蓝底的块类型，与 PR #314 定的「跨块选区整行蓝底对齐 Notion」口径
不一致。语义照抄 `DETAILS` 那支：整个被罩 → 标容器（既有行为不变）；部分被罩 → 钻进去逐行判，整行被罩
就标这行且**不再下钻**（子行本就含在它盒里，再标一层会叠出双重底色）。
⚠ **行级蓝底必须配收窄光晕**：相邻 `<li>` 间距只有 4.8px（`:where(li){margin:.3em 0}` 折叠后），而默认
spread 是 4px——两行各向外 4px 合计 8px > 4.8px，中间叠出 alpha 更高的带（`.16` 叠 `.16` ≈ `.29`，比本体还深），
两行糊成一条、看不出选了几行。`li` 特化收到 1px，留 2.8px 干净缝。
`rangeSelEls` 只做视觉记账——操作走 `selectedTopBlocks` 独立算连续跨度，故本条纯改「画」不改「做」；
门里 RS-6 直接钉这条：上色作用的行集合必须与蓝底标出的行集合**逐行相等**（多画一行是误导、少画一行是
漏报，PR #395 I4 的教训）。门：`e2e/list-rangesel-rows.spec.js` 6 条。

**「每行独立成块」的架构题**（Wendi 2026-08-05「按说这两行应该没有任何关联」/「你看 Notion 怎么搞的我们
就怎么搞」）：Colin 2026-08-06 拍板本轮**不动存储模型**，带实测成本单单独回给 Wendi 拍——三笔成本（编号
连续性无兜底 / 嵌套要重开 7-24 刚拍的「列表层级只用 DOM 嵌套」铁律 / md 往返在外部编辑器统一 marker 后
会静默塌回一整张）见 `docs/brainstorms/2026-08-06-todo-row-independent-block-costing.md`。

**行级拖拽重排（粒度对齐 U2=B，分支 feat/ux-granularity，2026-08-03）。** 行悬停起拖 = 拖**单行**（幽灵图=整行）；指示线亮在目标行上/下**半区**（指针半区语义，对齐 Notion 落点直觉）。落点语义：①同类列表（标签一致 + ws-todo 语义一致）内/间 = li 移动；②非列表块旁 = 拆出成**继承源类型**的独立单行列表块；③跨类型（todo↔普通 ul/ol）**允许，且被拖的行类型不变**（E3，2026-08-04 对拍定稿，推翻 v1 的「拒收」）——Notion 每块自带类型、没有列表容器，拖过去类型不变；我们是 `<ul>` 容器模型，保住类型只能**在落点把目标列表劈开**、插一张源类型的列表，视觉终态一致（一个待办行夹在两个圆点行之间）；④拖进自己子树拒收。源列表被掏空 → 移除（嵌套 ul 移除保宿主 li；toggle 体内列表清空 → 补空 p 保「体 ≥1 块」铁则）。每次成功 drop 记一个 checkpoint（undo 一步整体还原）；取消/无效落点零变更零 checkpoint。勾选态（`data-checked`）与 `id` 随行迁移保真。**整块拖拽仍可用**：Esc **两次**灰选整张列表后拖 = 整列表（`selectedEl` 优先于 `hoverRow`）——2026-08-05 起 Esc 在列表里是三档，见下条；契约本身一字未改，只是入口往后挪了一次按键。**落点横向偏移 = 嵌套层级（E4，2026-08-04 对拍定稿，原「绑 #337 等拍板」已解除）**：Notion 实测三条——参照系是**页面内容列左缘**（顶层段落文字左缘，**不是**列表行文字左缘，这点极易搞错）；每约 **26px** 一个层级；层级被 **「上一行深度 + 1」钳死**（落点右移 220px、理论 8 级，实测仍只嵌一级）。指示线按 Notion 重做：蓝线**左端带一个圆点**标层级、线随目标层级右移；**将成为子项时父行整行淡蓝底**。与 #337 不冲突——#337 争的是 **Tab 键**的语义（嵌套 vs 视觉缩进），拖拽落点产生的是真结构嵌套 `<ul><li><ul>`，Schema 本就支持，Notion 两者都有。⚠ 两个实现约束：指示线**只能用 `::after`**（`.ws-todo > li::before` 是勾选框）；缩进量**必须走 `data-ws2-dropindent` 属性、绝不写 inline style**——块级 `style` 即非合规，自动保存万一撞上拖拽窗口就把整篇判成降级。门：`e2e/list-row-drag.spec.js`（14 条，含「指示线画的层级必须与实际落位同源」——变异自检证明这条不冗余：把画的那一侧单独打歪，只有它翻红）。

**手柄菜单行级作用域（粒度对齐 U3=C，分支 feat/ux-granularity，2026-08-03）。** **两个入口两种作用域**：①**行锚手柄**（悬停行后点 ⋮⋮）→ 菜单作用于**该行**，打开时只高亮那一行（`data-ws2-selected` 挂 li，纯交互态不入盘）；②**Esc 灰选**整块后点 ⋮⋮ → 维持**块作用域**（既有行为一字不动）。行作用域各项语义：**转为**=抽出该行转成目标块、前后剩余项仍是原列表（复用 #346 `turnIntoLines`）；**在下方插入**=在同列表插入新的空行并落光标（不是列表后的段落）；**复制**=复制该行紧随其后、副本剥 `id`（防锚点重复）；**删除**=只删该行，删空后收敛（顶层列表 de-list 成空段落并进编辑；嵌套子列表移除、宿主行保留、光标回宿主行末；toggle 体内因 de-list 产 `<p>` 天然满足「≥1 块」铁则）；**颜色**=`ws-color-*` 上在该行 li 上（整列表与同列表其他行不受影响，空 class 剥除）。行作用域菜单开着时 **Esc = 关菜单 + 清行高亮**（此前该态下 Esc 空转；块作用域的 Esc 阶梯不变）。**实现约束**：行模式**不设 `selectedEl`**——它是「块灰选」状态，塞 `<li>` 进去会让 Delete 键与 `removeBlock` 的 `topBlocks` 计数按块语义误伤。门：`e2e/list-row-menu.spec.js`（9 条）。**菜单项集不扩**：Notion 的 Color/Move to/Comment/Ask AI 等逐项另议，本单元只改作用域。

**gutter「+」快捷插入钮（粒度对齐 U4=D，分支 feat/ux-granularity，2026-08-03）。** ⋮⋮ 手柄左侧一格常驻「+」，**与手柄同显同隐**（显隐统一走 `setGutterVisible`——分开控制必漏一处、产幽灵按钮）、与手柄同一水平线、`cursor:pointer`（与手柄的 `grab` 区分）。**插入产物 = 普通正文块，严格对齐 Notion**（Colin 2026-08-04 拍板方案 A；实测 Notion 的「+」永远插普通文本块，与当前块是不是列表行无关，中间行/末行双探针证）：**顶层行**上点「+」→ 在该行下方插入空正文块，落点在列表中间时把列表劈成 `[前段列表][段落][后段列表]`，切点在首/末则退化为插到整个列表前/后（**不产空列表**）；**非列表块**（或 Esc 灰选整块）→ 下方插入空正文块。**⌥ 点击插到上方**（对齐 Notion 的 `Click to add below. Option-click to add a block above`，实读其 aria-label）。插入后光标落新块，一次 undo 整体还原（劈开的列表也一并合回）；`title` 走 i18n（`editor.plusTip`，zh/en 双词条）。门：`e2e/list-row-plus.spec.js`（10 条）。
⚠ **嵌套行是结构性分歧、不是产品选择**：Schema 规定 `<li>` 只能装行内内容或嵌套列表（`li-content` 规则），**段落无法存在于嵌套层**，故嵌套行上的「+」退而插入同层新行。这是文法约束下最接近的可用行为，与 Notion 的差异记录在案。

## 行单元契约（E，2026-08-07，Colin 拍板 E→A1 路径第一步）

缘起：`docs/brainstorms/2026-08-07-notion-block-model-alignment-research.md` §3 方案 E——#421 式 bug 的复发条件是「交互必须下沉到行」只存在于口口相传，本节把它变成有形制度。代码锚点：`src/editor/blockedit.js` 的「行单元解析层」注释块（`rowOf` / `caretRowOf` / `topLiIn` / `tabLineHostOf` / `containerFirstLineHost` / `caretLineHostIn` / `paraOf` / `isRowAnchor` / `rowSelEl` 九个 helper）。「行」= 列表的 `<li>`、多段容器（callout/quote）的直接子 `<p>`。三条规则：

1. **取用规则**：任何按行作用的交互，作用单元必须经行单元解析层获取。禁止拿 `blockOf` 产物当「行」（它对列表返回整个 `<ul>`——#421 一族的根）。裸 `closest('li')` 只允许「就地 + 归属检查（`host.contains` / `parentElement === host`）」的内联形态；新代码优先用命名 helper。
2. **完备性规则**：新增块级交互（高亮/选中/手柄/菜单/拖拽/删除/插入/…）必须**同 PR** 在矩阵门 `e2e/row-unit-matrix.spec.js` 补行 fixture 用例——矩阵表每格必须是「有用例」或「有理由的 n/a」，不进矩阵不许合。
3. **断言时点规则**（#421 的血教训：v0.12.2 的门操作序列与用户复现逐字相同、却只看按完 Esc 之后）：行级门必须在交互态**存续期间**断言（编辑中/选中中/拖拽中的那个时刻），不许只断言操作序列结束后的终态。门覆盖的是「时刻」，不只是「序列」。

A1（li 升一等交互块，worktree `wordspace-next-rowblock` / `feat/row-block-identity`）落地后，本契约第 1 条由块身份自然承担，第 2、3 条继续有效。

## 有意分歧

- **编辑器架构本质不同**（历史形成，两侧独立演进）：ui-demo 是受控 React 块模型，真 app 是每个块独立 contenteditable、直接改真实 DOM。**本 spec 的行为契约主要约束真 app 侧**；ui-demo 侧 todo 行为**尚未审计**（见欠账）。谁拍板/日期：架构分歧属既有事实，本 spec 首次记录在案（2026-07-23）。
- **⌘A 分级选中的粒度是整个 `<ul>`（不是单个待办项）**——有意设计，见 `docs/features/editor-select-all.md`，与 Notion 的 item 粒度是拍过板的分歧。
- **嵌套子项保持圆点子列表、不可勾选**（Colin 2026-07-22 拍板，PR-C U11 已落地）：`bullet「转为」todo` 只作用于顶层列表，裸嵌套子列表保持自身类型显圆点、不可勾；**Tab 缩进产生的 `ws-todo` 子列表保持 todo 行为**（D3 既有设计，子项有勾选框、可勾选）。
- **多项列表↔文本转换往返不保留勾选态**（Colin 2026-07-22 拍板，PR-C U10 已落地）：todo→文本→todo 回程只恢复列表结构，勾选态丢失。
- **含子列表的勾选项不划线、只变灰**（PR-C U14）：CSS 装饰传播规则下 line-through 无法从后代取消，为不划穿未勾子项，含子列表的勾选父项退而只变灰（叶子勾选项照常灰+划线）。

- ~~**多级裸嵌套 marker 层级不区分**（PR-C U11）~~ → **2026-08-04 已解，同日复跑对拍时更正过一次**：Notion 实测——**圆点**逐级循环 •/◦/▪（`ul ul`→circle、`ul ul ul`→square、第四级回首档），**编号每一层都是十进制**（1. 2. 3. 逐层重新起数，**没有** a./i.）。所以只给 `ul` 加循环规则；`ol` **不写** `list-style-type`，浏览器默认正好就是逐层十进制。⚠ 更正记录：上一批曾按「1./a./i.」给 `ol` 也加了循环——那是**没量就照 Word/Google Docs 惯例改的**，属于我们自己制造的漂移；复跑对拍时用 Notion 的 `--pseudoBefore--content` 字面值（二级项就是 `"1."`）实证并删除，且补了「带旧规则的文档打开即自愈」的回归门。**todo 内部的裸嵌套列表维持 disc/decimal 不变**（`.ws-todo ul:not(.ws-todo)` 类选择器压过零权重 `:where()`，PR-C U11 的设计意图保留）。门：`e2e/list-nested-markers.spec.js`。
- **整表上色的 todo 里勾选父项的子列表被重置回正文色**（PR-C U14，P3 纯视觉）：给整个 ul.ws-todo 上 ws-color 主题后勾选带子列表的父项，子列表文字被 `color:#37352f` 重置、脱离主题色。非回归（改前继承成灰更糟），CSS 无法既反制灰色下渗又保留任意祖先主题色，属固有局限。
- **`<ol>` 中段空项脱列后，后半段序号从 1 重启、不续接**（PR-D U15，by-design）：`ol[start=5]` 在中间空项 Enter 脱列后，后半 `<ol>` 只带 `class`、不带 `start`，C/D 显示为 1/2 而非 6/7。对齐 Notion/Docs（也重启），conform 不破；`ws-todo` 是 `<ul>` 无编号、不受影响。续接需按拆分位置重算 start（还要扣掉被删空项），复杂度不匹配收益，留作后续。
- **深色模式下勾选框「已勾蓝底」对比压缩**（PR-E U25，记录制 / R8 时间盒）：文档反色配方 `invert(1) hue-rotate(180deg)` 是根滤镜，对饱和蓝的亮度/色相变换非线性，已勾蓝底在深色下对比被压到 ~1.25:1（浅色侧 4.5:1）。**浅色已达标**（本 PR 修）；深色侧无低成本 CSS 解——伪元素勾选框无法像 `img` 那样进反色豁免（豁免按「元素」选择，`::before` 选不中），改配方会动全局深色观感。加深的**未勾灰边框**经反色仍高对比、不受影响。建议：接受现状或排 backlog 专项深色勾选框配方，待 Colin/Wendi 拍板。
- **深色模式下文本 emoji 被反色滤镜扭曲**（PR-E U27，记录制 / R8 时间盒；非 todo 专属，todo 场景最显眼）：根滤镜把 emoji 字形当普通彩色像素处理 → 颜色乱移、亮度不均。**实测**（canvas 复刻 `invert(1) hue-rotate(180deg)` 对字形像素）：🙂 亮度降到 37%、🔥 57%、✅ 71%、🎉 80%，而 📌 反被提亮到 160%——不是均匀压暗、是逐 emoji 色彩畸变，无法用单一参数调平。`img` 有双反豁免、字体 emoji 不在豁免名单，且 **CSS 无法按「字符是 emoji」选中文本节点**（本单元真难点）。唯一有效解是 JS 遍历文本把每个 emoji 裹进双反 span——需跑全文档 + 每次编辑重跑，超低成本预算。建议：接受现状（emoji 仍可辨认）或排 backlog JS-wrap 方案，待 Colin/Wendi 拍板。
