## 两条架构护栏（「不出灾难」的具体含义）

**① 存储层一律不动。** Schema 决策4 的文法保持原样：callout/blockquote 只装 phrasing 或 `<p>`、
不装列表/表格/别的块。**容器化只做交互层**——手柄、菜单、选中、Enter、拖拽的作用单元下沉到框内
`<p>`，磁盘上仍是一个 `div.ws-callout`。这有直接先例：todo「每行独立」方案 B 就是「存储单元
（磁盘一个 canonical ul）与交互单元（per-li）解耦」，Colin 真机验过「手感非常好」。
被文法挡住的终态（例如把列表拖进框内）做到边界为止、spec 记「结构性分歧」——21 条差异里没有
任何一条的 Notion 目标行为要求非法结构（C11 拖入的是段落，入框合法），所以这条护栏与「全按
Notion」零冲突。动文法 = 动 Wendi 的范式地基，才是灾难源。

**② 只推广已验证的机制，不发明第二套。** 行级手柄那一整套（`rowOf` 悬停行解析 / `hoverRow` /
`gripRow`（作用对象单一真相源）/ `menuRow` 行作用域菜单 / 行拖拽 / 行「+」）已经在列表上跑通
（U1-U4 + I4 收口），容器化 = 把「行」的定义从「list 的 `<li>`」推广到「multiPara 容器的直接子
`<p>`」。表格行/列手柄同理挂在同一个 gutter 体系上。**判据单一真相源**：`isMultiParaContainer`
（已有）、`SM.PHRASING_TAGS`、`rowOf` 泛化后仍是唯一的悬停行解析器。

### PR-1 五处零反馈边界（industry practice 拍板）

| 边界 | 拍板 | 依据 |
|---|---|---|
| 引用/提示框**末行 Delete**（下一块是叶子文字块） | 前向合并：下一块内容并进容器末段，块消失 | C8 的镜像；本仓已有「Delete 块末=镜像 Backspace 块首」先例（U7/select-3 列表前向合并）；Notion 同语义 |
| 引用/提示框末行 Delete（下一块不可并：图/表/toggle/容器） | 不吞不动，与 Backspace 侧「prev 不可并」既有约定对称 | 同上 |
| 表格**后**一块行首 Backspace | 不删任何内容，光标移入表格**末格末尾** | Notion/Google Docs 一致：跨结构边界的第一次删除键只移动光标、不隔墙拆结构（「先进入再删」） |
| 表格**前**一块末尾 Delete | 对称：光标移入表格**首格开头** | 同上 |
| 折叠块后一块行首 Backspace（当前块非空） | 不吞内容，光标移到 toggle 可见末端（收起=summary 末；展开=体内末块末尾） | 与既有「toggle 体首块退格→光标回 summary」对称；不隔墙拆结构 |

注：`flashNope` 原语已退役，不复活——这批的解法全部是「键有真实效果（移动光标/合并）」，
不需要「无效提示」这个概念。

### PR-3 callout/quote 容器化核心（C1/C2/C5/C6/C7/C9/C11）

Notion 的模型（对拍实测）：**首段悬停给容器手柄（框外左侧、钉框顶，作用=整框），其余段给段手柄
（框内、对齐该行，作用=该段）**。段菜单标题 "Text"、删除只删该段（C2）；「+」插到该段下一个兄弟、
留在框内（C5）；框内 Enter 劈段不劈框、框末 Enter 新段留框内（C6/C7）；Esc 选中该段（C9）；
外部段落可拖入框内成为子段（C11，段落入框合法）。

实现要点：
- `rowOf` 泛化：入参块是 multiPara 容器时返回「悬停的直接子 `<p>`」，**首段返回 null**（= 容器
  手柄，Notion 同款）。混排裸行内内容（外部文件才有）视作首段的一部分 → null。
- 段作用域菜单/拖拽/「+」全走既有 row 通道（`openBlockMenu(el,row)` / `dragFrom=row` /
  插入按 row 定位）；`removeRow` 推广成「删 `<li>` 或删框内 `<p>`」，掏空收敛复用 C8 终态
  （掏空的框不留）。
- Enter：编辑态在 multiPara 容器内 → 自管劈段（`<p>` 劈 `<p>`、尾部新 `<p>`），不再走「新建
  框外正文块」分支。undo 一步一段。
- Esc：光标所在段打 `data-ws2-selected`（复用行模式「不设 selectedEl」原则——`<p>` 不是顶层块，
  塞进 selectedEl 会让 Delete/removeBlock 的 topBlocks 计数误伤，行模式已踩过）。
- 拖入（C11）：内部块拖拽 dragover 落到框内段上 → 指示线画段间，drop 把段落插为框内兄弟。
  仅段落/标题等 phrasing 载体放行；列表/表格/图片仍落框前后（文法边界，spec 记分歧）。
- 风险最大点：blockOf/作用域机制对「框内 `<p>`」的处置遍布 keydown。凡「作用单元=块」的既有
  分支（⌘A 分级、跨块选区、块级删除）保持以整框为块——容器化只接管 gutter/菜单/Enter/Esc/拖拽
  五个口子，**不改 blockOf 本身**（改它 = 影响半径失控 = 灾难源）。

### PR-4 表格 Notion 化 A（T1/T5/T7/T8/T9/T11）

- T1/T5：**三套手柄并存**——块手柄（既有 gutter ⋮⋮，恒锚整表）+ **行手柄**（表左缘外 6×18，
  y 随悬停行）+ **列手柄**（表顶外 18×6，x 随悬停列）。行菜单 `[颜色? 上方插行 下方插行 复制
  清空 删除]`、列菜单 `[左插列 右插列 复制 清空 删除]` **按轴切干净**（Notion 项集实测）；
  现行「格内开块菜单出行列混合操作」退役，T7 的「两种前置状态菜单不一致」随之消解。
- T8：插行参照 = 手柄所指的那一行，插后焦点同列。
- T9：**退化守卫换向**——只剩最后一列时列菜单**无「删除」项**；只剩表头行（或最后一行）时行菜单
  同样无「删除」项；表恒 ≥1 行 ≥1 列。现行「允许删成退化态再自动补救」的收敛路径删除。
- T11：末格 Tab **不再长新行**（Notion 实测：编辑框停在末格）。加行走行手柄/边缘入口。
- 行/列手柄挂 gutter 体系：作用对象进 `gripEl/gripRow` 同一真相源（I4 不变式：画的=做的），
  新增 `gripCell` 类状态**不另立**——行手柄的作用对象就是 `<tr>`，列以索引表达（menuCol）。
