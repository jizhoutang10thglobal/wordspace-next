## 0. 开工前必须先纠正的一条认知（本轮最重要的发现）

昨晚的报告把第①条写成「Notion 行首退格**不合并**，我们**合并**，二者互斥」，
并据此说「改就是推翻 #319（Wendi bug3）」。**这个描述是错的。**

今天用 `pressKey` + JS 设光标的组合重新对拍（见 §1 探针记录），实测：

| 按第几次 | Notion 的结果 |
|---|---|
| ① | 该行**剥掉列表格式、原地变成文本块**，列表在此处劈开，**不合并** |
| ② | 此时是普通文本块，**并入上一块**（`段落乙` + `待办一` → `段落乙待办一`） |

嵌套行是**三步**：① 剥格式（仍留在嵌套层）→ ② 升到顶层 → ③ 合并。

**结论：Notion 是「逐层剥离」，最终仍然会合并，只是把合并推后一次按键。**
所以按 Notion 改**不会**让 Wendi 那条「行首退格什么都不发生」的 bug 回来——
第一次按键就有明确可见的反馈（bullet 消失、行变文本），第二次给出原来的合并结果。
`#319` 的修复意图（消灭零反馈死胡同）完整保留，只是多了一个中间态。

## 1. 本轮对拍探针记录（今日实测，2026-08-04）

fixture：Notion 页面「对拍fixture-拍板五项-v2」（MCP API 建，避开打字/IME 脆弱面）。

### harness 硬知识（写进 skill，会重复踩）

- **Notion 只认它自己那套键盘层**：`cdp('Input.dispatchKeyEvent')` 发的原生键事件
  Notion **完全无视**（Backspace/Delete 连按无反应），必须用 ego-browser 的 `pressKey`。
  但 `Input.insertText` 是有效的——所以「能插字」不能证明「能发键」，别用插字做连通性探针。
- **浏览器窗口在后台时鼠标点击不做命中测试**：`document.visibilityState === 'hidden'` 时
  `click([x,y])` 静默失败，光标停在原处不动。`Page.bringToFront` 拉不起来。
  **可靠替代：用 JS 设 DOM selection（`ce.focus()` + Range collapse）+ `pressKey`**——这个组合
  实测有效，且完全不依赖窗口可见性。
- **哑探针警报**：上面那个失败模式极阴险——每次点击都"成功"返回，光标却没动，
  于是连按几次 Backspace 全落在**上一个**目标行上，读出来的是一串看似合理、实则完全错位的结论。
  **凡是靠点击定位的探针，必须在按键前回读「光标此刻在哪个块」并与目标核对**，不核对就是假证据。
- 依赖 hover 才出现的 UI（Notion 的 gutter 六点/「+」）在窗口隐藏时**取不到证**：
  CDP mouseMoved、JS 合成 MouseEvent 都唤不出。要测这类必须窗口在前台。

### 实测结论表

| # | 场景 | Notion 实测结果 |

| E1-a | 顶层圆点行（中间行）行首退格 ① | `bulleted_list :: 圆点三` → `text :: 圆点三`，原地，列表劈开 |

## 2. 结构性天花板：三处「按 Notion 做」做不到字面一致

Notion 的模型是「每个块自带类型 + 任意块都可以有子块」；我们是**受限 HTML 文法**
（`docs/html-kernel-boundaries.md` + `schema-validate.js`），`<li>` 只许装行内内容或嵌套列表，
`<p>` 不能有子块。因此下面三处只能取**结果等价的最近映射**，不是产品选择、是文法约束：

| 处 | Notion | 我们能做到的最近映射 |
|---|---|---|
| 嵌套行退格 ① | 变成「嵌套的文本块」 | 表达不了 → **一步到 Notion 的 ②**（升为顶层文本块） |
| toggle 降级 | 子块仍挂在降级后的文本块下 | `<p>` 不能有子 → **子块提升为其后的兄弟**（= Notion ② 的形态） |
| 嵌套行「+」 | 插入嵌套的文本块 | 表达不了 → 插同层新行（**已登记，本轮不动**） |

这三处都写进 spec 的「有意分歧（文法所限）」节，并注明**它们只是把 Notion 的多步压成一步，
终态与 Notion 一致**。除此之外的所有差异一律按 Notion 改，不再逐项讨论。

## 3. 单元拆解

### E1 · 行首退格改成「逐层剥离」 —— 最重、风险最高，先做

**改什么**
- 顶层非空列表行、光标在行首 → **不再合并**，改为「该行转成文本块、列表在此劈开」。
  这正是 U3 行菜单「转为正文」的 `turnIntoLines(row, 'text')`，且它刚被对抗审查 P1-1/P1-2
  加固过（保子项、不落中间态快照）——**接线复用，不新写**。
- 第二次退格：此时已是 `<p>`，落进既有 generic 合并分支，**零新代码**自动得到原来的行为。
- 嵌套非空行 → 抽出成顶层文本块（§2 映射）。`turnIntoLines` 目前对嵌套行返回 `null`
  （P1-2 的修复），需要**新增**「嵌套行抽出」能力：抽出后的落点、以及**后续兄弟子项的归属**
  要先补测 Notion 再定（不许猜——skill 铁律②）。
- **空列表行**行首退格（现在走 Wendi bug4 那条独立分支）：Notion 行为**未测，必须补测**。
- 标题块（h1-h4）行首退格 Notion 是先降级成文本还是直接合并：**未测，必须补测**。

**既有门的预期迁移（本单元最容易出假绿的地方）**

这四条现在断言「一次退格就合并」，改语义后必然翻红：

| 文件:行 | 用例 |
|---|---|
| `e2e/app.spec.js:457` | Wendi bug3：第二个列表块行首退格 → 并入上一块 |
| `e2e/app.spec.js:475` | Wendi bug3：段落后接待办，待办项行首退格 → 并入段落 |
| `e2e/todo-delete-forward.spec.js:119` | 回归：首项行首 Backspace 并入上一段落（#319 未回归） |
| `e2e/todo-nested-keys.spec.js:69` | 嵌套两项（前非空+后空）Backspace → 并入前项 |

**纪律**：每条的预期改动必须逐条写明「为什么新预期才是对的、它守住的用户诉求是什么」，
并且**改成两次按键后仍然断言最终合并结果**——只把中间态加进去，绝不把断言删弱。
「红了就改绿」是假绿的头号来源，这四条我会在报告里逐条列出改前/改后断言。

**新增门**：`e2e/list-backspace-peel.spec.js` —— 顶层/嵌套/todo/编号/空行/标题各一组，
每组断言「① 的中间态」+「② 的终态」+「磁盘 reparse 合规」+「undo 一步还原」。

**变异自检**：把 ① 的分支还原成直接合并 → 中间态断言必须全红、终态断言仍绿
（证明门测的是中间态而不是终态的顺带效果）。

**估时：4 小时**（含两处补测 + 四条既有门的逐条论证）

### E3 · 跨类型拖拽放开

**改什么**：`sameListType` 守卫从「拒收」改成「劈开目标列表、插入一个源类型的单行列表」。
Notion 拖过去类型不变，是因为它没有列表容器；我们 `<ul>` 容器模型下，**保持原类型 = 在落点劈开目标列表**，
视觉终态与 Notion 一致（一个圆点行夹在两个待办行之间）。
`rowDragOver` 放行跨类型（指示线要亮）；`rowDrop` 走劈开路径，复用现有「拖到非列表块旁拆出单行列表」的一半代码。
收尾要清理：劈开后可能留空列表、源列表掏空、toggle 体 ≥1 块铁则。

**门**：跨类型拖入首/中/末三个落点 + 勾选态保真 + undo 一步 + 磁盘合规。
**正对照防哑门**：同类拖拽仍真重排（证明探针有效）。

**估时：2 小时**

### E4 · 拖拽落点横向偏移 = 嵌套

**改什么**：`rowDragOver` 增读 `e.clientX`，与目标行文字左缘比较，超阈值 → 显示**缩进的**落点指示线；
`rowDrop` 插进目标行的 `:scope > ul/ol`（没有就建）。已有的自子树守卫继续生效。

**先补测**：Notion 的分界阈值到底在哪（20px=兄弟 / 250px=子项之间的临界点）、能否一次嵌两层、
指示线的视觉形态（缩进多少、是否带竖线）。

**与 #337 的关系**：不冲突，可以做。#337 争的是 **Tab 键**的语义（嵌套 vs 视觉缩进）；
拖拽落点嵌套产生的是**真结构嵌套** `<ul><li><ul>`，我们的 Schema 本来就支持（对拍 fixture 里就有）。
Notion 两者都有。若 Wendi 最后把 Tab 定成「缩进」，拖拽嵌套仍然成立。

**估时：2.5 小时**

### E5 ·「+」点下去弹块类型选择器

**改什么**：`openSlash(blockEl)` 现成可用，真正要改的是 `applySlash` —— 它假定用户**打过**字面 `/`，
会往回删 `query.length + 1` 个字符；从「+」打开时没有这个 `/`，会误删前面的内容。
加 `slash.typed` 标志，「+」路径置 false 时跳过删除。
「+」插入空块 + `enterEdit` 之后调 `openSlash(nx)`。

**先补测**：Escape 关掉选择器后 Notion 是否**留下**那个空块（决定我们要不要回滚插入）。

**影响半径**：这是**全局 gutter 行为**，影响所有块类型，不只列表——门必须覆盖段落 / 列表行 / toggle 体内。

**估时：1.5 小时**
